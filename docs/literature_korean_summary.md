# 논문 및 영문 보안 자료 한글 요약

- 목적: 영어 논문 제목과 보안 용어를 몰라도 이 프로젝트가 어떤 자료를 근거로 삼았는지 이해할 수 있게 정리한다.
- 적용 범위: `docs/final_security_report.md`, `README.md`, `threat_zap_comparison.py`, Jitsi Meet 모의공격 실습 문서에서 인용한 논문과 보안 기준
- 주의: 아래 내용은 논문 전문 번역이 아니라, 실습 보고서에 필요한 핵심 의미와 보안 적용 포인트를 쉬운 한국어로 정리한 것이다.

## 2. 영문 보안 용어 한글 해설

| 영문 용어 | 한글 의미 | 쉽게 말하면 |
| --- | --- | --- |
| STRIDE | 위협 모델링 분류법 | 시스템을 보고 어떤 종류의 공격이 가능한지 여섯 가지 관점으로 나누어 찾는 방법 |
| Spoofing | 위장 | 다른 사용자나 서버인 척하는 공격 |
| Tampering | 변조 | 요청, 토큰, 미디어 데이터 등을 몰래 바꾸는 공격 |
| Repudiation | 부인 | 나중에 “내가 한 일이 아니다”라고 부인할 수 있는 상태 |
| Information Disclosure | 정보 노출 | 회의 링크, IP, 토큰, 사용자명 같은 정보가 새는 문제 |
| Denial of Service | 서비스 거부 | 서버나 브라우저가 과부하로 정상 동작하지 못하게 만드는 공격 |
| Elevation of Privilege | 권한 상승 | 일반 참가자가 호스트나 관리자 권한을 얻는 문제 |
| OWASP ZAP | 웹 취약점 진단 도구 | 웹 사이트를 자동으로 둘러보고 보안 헤더, 쿠키, XSS 같은 문제를 찾아주는 도구 |
| Baseline Scan | 기준선 진단 | 비교적 안전하게 웹 응답을 살펴보는 ZAP 기본 진단 |
| Active Scan | 능동 진단 | 실제 공격 패턴을 보내 취약점을 확인하는 진단. 반드시 로컬 실습 대상에만 사용해야 한다. |
| Alert | 경고 | ZAP이 발견한 의심 취약점 또는 보안 설정 문제 |
| False Positive | 오탐 | 실제 취약점이 아닌데 도구가 취약점처럼 표시한 결과 |
| CSP | 콘텐츠 보안 정책 | 브라우저가 어떤 스크립트, 이미지, 프레임을 허용할지 정하는 보안 정책 |
| X-Frame-Options | 클릭재킹 방어 헤더 | 다른 사이트가 내 페이지를 iframe에 넣어 속이는 공격을 막는 헤더 |
| Permissions-Policy | 브라우저 권한 제한 정책 | 카메라, 마이크, 위치 같은 브라우저 기능을 어느 출처에 허용할지 정한다 |
| Cross-Origin | 교차 출처 | 현재 사이트와 다른 도메인, 포트, 프로토콜에서 온 리소스나 요청 |
| WebRTC | 브라우저 실시간 통신 기술 | 프로그램 설치 없이 브라우저에서 음성·영상 통화를 가능하게 하는 기술 |
| ICE Candidate | WebRTC 연결 후보 주소 | 브라우저가 상대와 연결하기 위해 수집하는 IP/포트 후보 정보 |
| TURN Relay | 중계 서버 | 사용자끼리 직접 연결하지 않고 서버를 거쳐 미디어를 전달하는 방식 |
| P2P | 사용자 간 직접 연결 | 서버 중계를 줄이고 참가자끼리 직접 연결하는 방식. IP 노출 위험이 커질 수 있다. |
| E2EE | 종단 간 암호화 | 중간 서버가 내용을 볼 수 없도록 송신자와 수신자 사이에서만 복호화하는 방식 |
| ReDoS | 정규식 서비스 거부 | 위험한 정규식과 입력 때문에 처리 시간이 폭증하는 공격 |
| DREAD | 위험도 점수화 방법 | 피해 규모, 재현성, 공격 난이도, 영향 범위, 발견 쉬움을 점수로 매기는 방식 |

## 3. 보고서 작성 시 쉽게 쓰는 문장

아래 문장은 영어 제목을 그대로 쓰기 어려울 때 보고서에 넣기 좋은 표현이다.

```text
본 프로젝트는 WebRTC 보안, IP 주소 노출, MFA 사용성, 화상회의 개인정보 재식별, P2P 미디어 경로, ReDoS, 통합 커뮤니케이션 보안, 화상회의 앱 개인정보 처리 논문을 근거로 삼았다. 영어 논문 제목은 부록에 원문 그대로 남기되, 본문에서는 각 논문의 핵심을 한글로 풀어 설명했다.
```

```text
STRIDE는 설계 단계에서 회의방 권한, 회의 링크, 미디어 키, 개인정보 흐름 같은 구조적 위협을 찾는 데 사용했고, OWASP ZAP는 실행 중인 웹 화면에서 보안 헤더, 쿠키, 브라우저 정책, 노출된 URL 같은 구현 취약점을 찾는 데 사용했다.
```

```text
Jitsi Meet 실습에서는 외부 공개 서버가 아니라 본인 PC의 로컬 self-hosted 환경만 대상으로 삼았다. Active Scan은 실제 공격 패턴을 보내므로 허가받지 않은 사이트에는 절대 실행하지 않는다.
```
